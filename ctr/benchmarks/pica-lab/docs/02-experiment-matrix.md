# Experiment matrix: proposed tests, falsifiable predictions

**Legend:** `[I]` implemented in phase-1 source; `[P]` specified, not yet implemented; risk `L` = ordinary legal render, `M` = tightly controlled low-level commands, `H` = special hardware behavior requiring isolated, opt-in hardware review. For every test, capture source parameters, actual command-list bytes, shader binary, output hashes, relevant buffers, all errors, and run metadata. All expected behavior below is a **hypothesis** unless explicitly cited as already documented.

## A. Rasterizer, primitive processing, interpolation

**R01 [I/L] Subpixel coverage grid.** H1: triangle edge coverage is quantized to a fixed subpixel lattice. H0: at every tested offset, coverage moves continuously or quantization is masked by viewport rounding. Move one triangle by offsets `k/64` px for k=0..63; then refine any first transition with k/256. Keep shape, depth, state, and visible area constant. Inspect full binary coverage masks and compare forward/reverse. A transition ladder with regularly spaced boundaries supports H1; irregular boundaries or shape-dependent thresholds reject a single global lattice. Output: shortest interval producing a coverage change, *not* an asserted internal number of coordinate bits. Run with rotations, winding reversal, and different edge slopes to reject a slope-dependent explanation.

**R02 [I/L] Shared-edge watertightness.** H1: two triangles forming a rectangle cover every pixel exactly once under a stated edge rule. H0: coverage has cracks or overlap at some orientations. Draw both diagonals at exactly the same coordinates with overwrite blending, then with additive blending to expose double hits. Repeat vertex order and half-pixel offsets. Look for gaps and twice-covered pixels using per-pixel masks. A difference between quad splits rejects simple watertightness; identical images don't prove all edges conform, so also test skewed quads. Output: pixel diffs and counterexample coordinates.

**R03 [P/L] Clipping boundary conventions.** H1: clipping follows the documented PICA clip-plane convention in homogeneous coordinates. Sweep a triangle vertex across left/right/top/bottom, near/far and `w` boundaries in controlled epsilon steps, with legal finite positions. Compare image plus attributes against a reference clipper with a documented threshold. Different pixels, degenerate fragments, or a different region mark a counterexample. Never intentionally feed NaNs or unbounded coordinates until baseline has been validated.

**R04 [P/L] Perspective-correct varying interpolation.** H1: texcoords interpolate in `attribute/w`, normalized by `1/w`, with quantization at a particular step. Feed a gradient lookup texture and vary w values (1, 2, 4, 8), holding projected screen-space geometry fixed. Compare to affine interpolation and multiple precision/rounding models. Regions that favor affine vs perspective predictions distinguish them; matching all models requires finer tests. Output: per-pixel error map and smallest distinguishing input.

**R05 [P/L] Depth and W-buffer quantization.** H1: Z and W paths quantize depth with different transforms/rounding. Repeated overlapping coplanar quads with controlled delta-z around depth equality and nontrivial w. Test 16-/24-bit depth formats separately, reversed draw order, comparison ops, depth writes, and polygon offsets. Binary-search the first value that changes visibility. A single fixed quantization rule predicting all comparison boundaries supports it; any mismatched boundary rejects it. Distinguish depth-buffer quantization from rasterized depth interpolation by testing constant-depth and varying-depth primitives separately.

**R06 [P/L] Early rejection timing and ordering.** H1: a fully hidden triangle avoids some texture/lighting work when early depth is active. Hold vertex, triangle, shading and memory inputs constant; alternate fully visible versus hidden surfaces, early-depth modes, alpha-test states, and draw order. Quantify queue-time difference and calibrated hotspot distribution. If hidden geometry costs the same across a texture-cost sweep, substantial early rejection is not supported under that configuration. A small timing difference alone does not establish a pipeline position; force expensive texture sampling to amplify stage-specific differences.

**R07 [P/L] Scissor inclusive/exclusive boundaries.** H1: scissor coordinates are inclusive on both ends, or another explicit convention. Sweep single-pixel lines and scissor box edges across exact integer boundaries; compare full output masks with predicted box conventions. A one-pixel discrepancy falsifies a convention. Repeat with nonzero viewport offsets to isolate scissor coordinates from viewport transform.

**R08 [P/L] Primitive setup scaling.** H1: setup cost scales primarily with submitted primitives, not covered pixels; H2: narrow or very long triangle geometry has an additional penalty. Compare 16..8192 non-overlapping tiny triangles, equal-count large triangles, long thin triangles, fully clipped triangles, and fully culled triangles. Keep shader instruction count fixed; warm caches and use geometric control. Fit slope vs primitive count and pixel count. If slopes follow covered pixels regardless of geometry, the setup-limited hypothesis is rejected. Beware command-list size and vertex attribute bandwidth.

**R09 [P/L] Sample positions / multisampling.** H1: enabled antialiasing uses a stable sample configuration, not a simple post-filter. Render thin diagonals and moving edges at fractions of one pixel; compare renderbuffer and display-transfer scaling options independently. Infer sample pattern only from several rotated edges; a single antialiased edge is underdetermined. Output heatmaps of coverage fractions.

**R10 [P/L] Face winding / degenerate primitives.** H1: winding and culling follow specified signed-area rules at subpixel boundaries. Sweep triangle determinant from large positive to near zero to negative while keeping one edge fixed. If culling switches at a threshold unrelated to orientation in quantized coordinates, reject pure signed-area rule. Use strictly valid geometry, no hardware-fault primitives.

## B. Color pipeline and output

**C01 [I/L] TEV stage arithmetic.** H1: each stage applies a particular intermediate quantization/clamp; H2: some operations retain more precision until the final stage. Use per-vertex color and constant multiplier, 0..255, and compare 1-stage, 2-stage and 6-stage chains. Choose adversarial operand pairs where early and late rounding differ, and change channel order while keeping total arithmetic equivalent. If stage chaining produces identical outputs to single-stage high-precision reference on all distinguishing cases, early-rounding models are rejected. Record alpha separately from RGB. Initial implementation sweeps 17 multipliers on stage 1 only: not enough to resolve all alternatives.

**C02 [I/L] Blending precision and factors.** H1: factors are evaluated using a specific 8-bit arithmetic and rounding rule; H2: additional internal precision is retained. Blend one colored rectangle over a known destination with source alpha 0..255; then invert source/destination, test ADD/SUBTRACT/MIN/MAX and separate alpha equation. Predict exact 8-bit channels under floor, round-to-nearest, and clamp-first models; store a minimal disagreement case. Initial implementation samples alpha in sixteenths only.

**C03 [P/L] Alpha-test/depth/stencil ordering.** H1: alpha rejection prevents depth and stencil writes (within specified state), and/or occurs before blending. Use a two-pass test: first pass has alpha below/at/above threshold and requests a stencil/depth write; second renders using stencil/depth predicate to reveal the first-pass side effects. Exactly predicted pixels distinguish ordering; control every mask. A failed expectation may indicate test configuration rather than a hidden pipeline stage; include no-test reference.

**C04 [P/L] Fog, gas, and lighting interpolation precision.** H1: lookup values interpolate with an identifiable precision or clamp rule. Sweep LUT coordinates over bins and discontinuities, compare neighboring input normals/depth values and different LUT contents. For fog and lighting, vary one scalar at a time. Output minimal counterexamples to fixed-point interpolation models. GAS must be split into its own mode and validated against Citro3D's experimental API rather than conflated with fog.

**C05 [P/L] Color-buffer format conversions.** H1: RGB565/RGBA4/RGB5A1 conversions use a stable rounding/expansion rule. Render high-precision gradients to each supported color-buffer format; transfer to matching linear output (not an unsupported conversion) and decode raw bytes. Compare 8→5/6/4-bit floor, truncation, and nearest models. Confirm byte order, alpha semantics, and restrictions. Do not use a transfer combination 3dbrew says may omit completion IRQ.

**C06 [P/L] Color write masks / logic operations.** H1: disabled color channels preserve their previous value exactly; H2: blend or logic operations affect masked channels before masking. Render a known RGBA8 sentinel, vary per-channel write mask and logic op, inspect full words. Any masked-channel change disproves strict final-stage masking, but confirm store/readback first.

## C. Texture units and memory system

**T01 [P/L] Filter precision and texel addressing.** H1: nearest and bilinear sampling use specific texel-center and fractional weight rules. Create a high-contrast 8×8 and 64×64 texture (known tiling), magnify 16×, sweep half-texel and 1/256-texel offsets and UV wrap modes. Fit competing address conventions and bilinear weight precision. Any pixel where predictions differ is a discriminating case; differing high-level images alone do not prove cache behavior.

**T02 [P/L] LOD computation and mip selection.** H1: texture level selection depends on log2(max(|dudx|,|dvdy|, ...)) with a particular bias/rounding. Build each mip level as a unique solid color. Sweep projected texture footprints, anisotropy, w, explicit bias and min/max clamps; infer exact level boundaries. Reject candidate rules when colors disagree. Keep cache effects out of correctness runs.

**T03 [P/L] Cache working-set thresholds.** H1: an effective texture cache has reproducible capacity- or set-conflict-driven throughput changes. First fix texels *actually sampled*, texture format, triangle count, fragment count and cache warm state while changing backing texture size alone; if throughput changes, the assumed same-request premise needs examination. Then vary footprint 4–256KiB using addresses and independent fixed sets with stable request count; randomize order. Validate a candidate capacity by shifting base address, using multiple formats, and changing 2-way/4-way conflict patterns. A single throughput cliff is **not** proof of cache capacity.

**T04 [P/M] Cache coherency and invalidation.** H1: texture updates by CPU, transfer engine, and P3D writer have different required barriers. For each writer, make a legal, synchronized control sequence that produces new texture A. Remove **one** cache invalidation/flush at a time, without introducing an unsupported race in the control. Render new color and compare. If omission never changes pixels under repeated cold/warm tests, a required barrier has not been demonstrated for that path. Hardware races need explicit nondeterminism labeling, not a single screenshot.

**T05 [P/L] Shared bandwidth and VRAM-bank placement.** H1: specific simultaneous P3D render-target reads/writes and texture access suffer bank contention. Allocate color/depth/texture in specific supported bank arrangements with recorded real allocations; run P3D-alone and PPF-alone references, then overlap workloads with controlled start points. Compute `T_overlap/(T_a+T_b)` and per-engine durations. Any non-overlap or bank-insensitive result weakens the contention hypothesis; distinguish bank constraints from insufficient VRAM, allocation fragmentation, cache hit rate, and synchronization overhead.

**T06 [P/L] Attribute-fetch alignment/stride cost.** H1: certain aligned vertex formats and strides improve attribute fetch; H2: cost is only fetched byte count. Use structurally valid layouts with identical semantic attributes and identical shader math; vary u8/u16/float representations and supported padding. Scan strides with explicit padding attributes per 3dbrew. Model timing against bytes and alignment. Never supply unsupported stride mismatches: documented to freeze GPU or fail to draw.

**T07 [P/L] Post-transform vertex reuse.** H1: repeated indices skip a material fraction of vertex shader executions via reuse. Compare `DrawArrays` replicated triangles against `DrawElements` with shared indices, while keeping pixel output/primitive count fixed. Increase unique-vertex reuse distance in an index stream, including a control that uses unique vertices but identical vertex values. If shader-hotspot counts and timing do not change with reuse distance, no caching benefit is established in this configuration. Control index fetch overhead separately.

**T08 [P/L] Procedural texture semantics.** H1: special procedural texture modes implement a particular LUT interpolation and coordinate mapping. Use one texel stage; step through controlled coordinates and LUT entries with discontinuities. Start with Citro3D's supported proc-texture API, record generated registers; then compare the emulator model. A single row of exact captured colors should distinguish competing interpolation models.

**T09 [P/L] Framebuffer cache coherency.** H1: a framebuffer-to-texture or framebuffer-to-PPF transition requires explicit flush but not necessarily invalidation under a known ordering. Render a rectangle to VRAM A, copy to B using PPF, then display/use as texture. Compare legal barrier sequences. Detect stale pixels using two distinct alternating colors and full captures, not only GPU idle flags. Do not read live buffers before completion.

## D. Vertex/geometry shader engine

**S01 [P/L] Dependent instruction latency.** H1: chains of 16..256 `ADD`/`MUL` instructions have greater incremental cost than equivalent sets of independent operations, due to dependency stalls. Generate paired assembly shader binaries automatically, verify disassembly and absence of dead instructions, consume all results, keep exactly the same draw and output. Sweep processed vertices at 128..65536, take timing slope after subtracting an empty shader. If independent and dependent slopes agree within noise across workload scales, the latency-hiding hypothesis is not supported. Opcode count alone cannot establish cycles per instruction without issue-width assumptions.

**S02 [P/L] Special-function throughput.** H1: `RCP`, `RSQ`, `LG2`, `EX2` have distinct issue/latency costs. Build valid instruction chains and independent lanes, vary arithmetic mix and number of processed vertices. Measure slope; cross-check with hotspot stage, and control exceptional inputs. If every instruction type gives same slope in a shader-limited regime, distinct functional-unit costs are not supported (but could be hidden).

**S03 [P/L] Vertex processor parallelism.** H1: throughput changes near occupancy thresholds reflecting physical vertex processors. With shader-heavy, pixel-cheap vertices, sweep independent vertex count and grouping, compare `DrawArrays`/`DrawElements` and geometry shader off/on. Graph time vs vertices, *not* just frames per second. A periodic step can be compatible with batching, cache lines, or issue width; require another shader length/attribute-size sweep before attributing it to three or four processors.

**S04 [P/L] Branch divergence and control-stack costs.** H1: mixed branch outcomes across vertices incur higher cost than uniform outcomes. Use conditional assembly with equal work per path, vary fraction and arrangement of vertices selecting each branch; record shader and vertex count. If only fraction matters, not arrangement, classic warp-style divergence is not supported; this GPU need not work like modern SIMT. Never deliberately overflow stack depths.

**S05 [P/L] Float24 operation models.** H1: a bit-exact model of `RCP`, `RSQ`, `LG2`, `EX2`, MIN/MAX, conversions and `CMP` predicts observable outputs. Use targeted values near exponent boundaries, exact halfway cases, signed zero, infinities and NaNs only where known safe. First build an observable encoding that can distinguish candidate float24 results; RGBA8 direct render cannot do it. Existing 3dbrew tests already cover many corner cases; aim at **remaining** uncertain rounding and approximate functions. A single mismatching distinguishing input rejects a model. Keep operand construction and upload conversion under separate test.

**S06 [P/M] Relative addressing and uniform precision.** H1: constant-register access and index arithmetic have a specific clamping/wrapping rule for *valid bounds*. Populate a table with unique safe values; vary indices within documented range using MOVA with intervening NOPs and controlled control flow. Compare outputs, cost and shader register traces. Never start with out-of-range offsets or adjacent MOVA instructions.

**S07 [P/M] Geometry shader emission and buffer reuse.** H1: SETEMIT/EMIT reuse follows the documented tentative four-vertex-buffer behavior. Generate valid primitives with unique vertex colors/positions and vary emission order and count, with known-good geoshader sample as baseline. A pixel whose identity differs from predicted reuse rejects the model. Separate geometry output semantics from throughput; cap total generated primitives. Geometry stage may change vertex-processor allocation, so do not interpret timing without an appropriate reference shader.

## E. GPU engines, commands, timing

**P01 [P/M] Hotspot sampler semantics.** Known: at 0x1EF00064/68/6C, eight u16 counters from four FIFO reads. Claimed: exactly one counter increments per sampling interval, with stage labels provisional. First test `GSPGPU_ReadHWRegs`/`WriteHWRegs` permission and error codes without interacting with other GPU work. Then in a serialized, opt-in module, measure idle, one isolated vertex-heavy, one raster-heavy, one texel-heavy, and one copy-heavy workload across legal interval lengths (3,4,8,16,32,64) and counts (64,256,1024). Validate sum-of-counters, repeatability, profiler-vs-GSP time, counter increment during idle, behavior when sampling ends, FIFO reset semantics. A change in a purported vertex counter under **only** fragment fill falsifies the simple label or indicates overlap/limitation. Never leave profiler enabled across module teardown.

**P02 [P/L] GSP per-engine performance log.** `GSPGPU_SetPerfLogMode`/`GetPerfLog` are available in modern libctru. Enable, discard first frame (known GSP initial-value issue), capture `totalDurationUs` deltas for P3D, PPF, PSC and scanout where supported. Compare monotonicity against number of issued commands; label potential 32-bit wrapping and concurrency. If a purported P3D increase appears only in PPF, investigate queue measurement instead of asserting raster pressure. This is *not* the same facility as the hotspot profiler.

**P03 [I/L] Draw submission/state overhead.** H1: same 192 triangles cost measurably more with 64 draw calls versus one. Alternate ABBA and keep command list within fixed buffer budget. Examine GPU queue duration and later CPU preparation cost. If no difference above noise, per-draw GPU overhead is not established; a CPU-side penalty may still exist. Extend to 1,2,4,8,16,32,64,128 calls, and hold vertex count strictly constant. Initial source implements endpoints only.

**P04 [P/L] Command stream state-change overhead.** H1: repeated writes to registers trigger cost beyond their byte count. Use legal no-op or identical-value state writes compared with equal-length command lists containing distinct benign writes, measure command processing time at 1..4096 writes. If equal-length command lists have the same slope, state change penalty beyond command parsing is not established. Use GPUCMD command header tests with command-list dump and bounded length.

**P05 [P/M] P3D/PPF/PSC overlap.** H1: GPU 3D, display transfer and memory-fill engines can overlap under specific buffer independence conditions. Use three *disjoint* VRAM buffers and verify outputs; measure each alone, serialized pairs, and queued pairs with permitted dependencies. If paired time approaches max(a,b), overlap supported; if sum(a,b), serialization supported; intermediate case underdetermined. Confirm with GSP perflog; don't infer overlap from wall-clock CPU timing alone.

**P06 [P/M] Completion/barrier contract.** H1: P3D completion, framebuffer flush, PPF completion and CPU invalidation guarantee distinct visibility. For each writer-reader pair, first prove a legal reference sequence. Then alter only one barrier at a time, across alternating color epochs, and record all 256² pixels. If stale pixels appear only when a specific barrier is removed, that barrier matters for that use. If results vary across runs, report race/nondeterminism, never make a reliability guarantee.

**P07 [P/L] GPU queue length/pacing.** H1: queue startup costs can be amortized by longer legal command lists, until another bottleneck. Vary number of identical simple operations per queued list, constant total work; measure completion events with and without forced waits. A per-list overhead appears as an intercept. Check that queue gets truly drained between conditions, and no C3D framerate limiter/VBlank synchronization is mixed in.

**P08 [P/L] Display-transfer behavior and PPF limits.** H1: transfer time scales as fixed startup plus bytes moved, with format- and alignment-dependent discontinuities. Benchmark only **documented supported** format pairs and dimension constraints, use widths 64..512 with proper alignment and height >=16. Each transfer must have a completion event and exact output verify. A throughput discontinuity at an alignment boundary falsifies a pure bytes-only model. Never use invalid line dimensions—known potential GPU hangs.

## F. Specialized or poorly-understood modes

**G01 [P/H] GAS mode.** H1: Citro3D's experimental GAS path can generate a reproducible accumulation/render image matching a proposed two-stage model. Inspect `citro3d/source/gas.c` and header first, reuse existing control setup and legitimate LUT values; sweep one parameter (attenuation/lighting/depth) at a time. Capture exact frame outputs and counter distributions. If changing a parameter produces zero difference, first prove that GAS mode is enabled and that a known-good smoke test responds. Do not jump from zero response to 'hardware ignores register'.

**G02 [P/L] Fog/lighting LUT boundaries.** H1: LUT table edges use one of several clamp/wrap/interpolate conventions. Build LUT with sharp distinct color/brightness values, sweep indices and small fractions at boundaries, holding all light vectors constant. Compare model-generated output images; each mispredicted pixel falsifies the rule.

**G03 [P/M] Unknown readable registers (non-destructive survey).** H1: certain currently unnamed *readable* external register fields correlate with GPU state. On idle, submit safe known-good workloads; read only known-safe read addresses and compare with reference. Never blindly enumerate registers, especially FIFO/autoincrement or status/IRQ-sensitive addresses. Treat zero, service error, permission denial, and a changing value as distinct observations. No writes until mechanism is understood.

**G04 [P/L] Shader output map and attribute clock gating.** H1: enabling unused attribute clocks / output semantics causes measurable activity or changes in interpolation. Use only valid, fully-written shader output maps, vary one enabled semantic and produce equivalent final pixels. If time difference persists after matching output attribute byte count, investigate clock-gating effects. Capture actual register sequence and do not violate output write-once rules.

**G05 [P/M] Geometry restart semantics.** H1: triangle strip/fan primitive restart flushes all internally held primitive state according to documented conditions. Feed unique-color vertices, issue restart between small strips, compare output against separate draws. Different outputs falsify equivalence. Use documented legal restart sequences; never infer hardware corruption from invalid command combinations.

## Proposed order / stopping rule

**First:** R01, R02, C01, C02, P03 plus selftest. **Second:** P02, R03, R05, T01, C05, S01. **Third:** P01, T03, T05, T07, P05, S05. **Last:** G01, G03 and risky shader/texture corner cases.

Stop an entire family if the baseline fails, command submission errors, a GPU wait exceeds a deliberately conservative user-configurable timeout, state is unstable between repeated controls, or a prior run produced visual corruption. Never attempt to automate recovery from GPU hangs by launching more risky tests.
